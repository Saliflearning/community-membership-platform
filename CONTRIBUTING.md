# Contributing

1. Create a focused branch from `main`.
2. Use synthetic data only. Never add real member, contact, payment, provider,
   demographic, or organization-confidential information.
3. Add tests for behavior or security-boundary changes.
4. Run `npm run verify`, `npm run test:safety`, and
   `npm run test:safety:history` before opening a pull request.
5. Keep implemented behavior, production prerequisites, and future work clearly separated.

Security issues belong in private vulnerability reporting, not ordinary pull requests.
